## 3. Source quality policy

## 4. Conflicts and resolutions

1. **OSM2World licence conflict (unresolved):** repository `LICENSE.txt` and GitHub API say **MIT**; OSM Wiki infobox says **LGPL**. Primary-source evidence favours MIT, but a maintainer confirmation is needed before treating OSM2World code as MIT for any vendoring. Recorded in `research/notes/procedural.md`.
2. **Microsoft GlobalMLBuildingFootprints count inconsistency (unresolved):** README introduction states 1.4B buildings; FAQ states 999M. Does not affect the licence conclusion (CDLA Permissive 2.0) but affects dataset-size estimates.
3. **WASI TCP/UDP default conflict (unresolved, resolve defensively):** `WasiCtxBuilder::new()` docs state TCP/UDP allowed but all addresses denied by default; `allow_tcp` docs state it is disabled by default. Mitigation: explicitly deny all network in host code regardless. Recorded in `research/notes/plugin-security.md`.
4. **ONNX Runtime GitHub repository unreachable (2026-11-27):** `microsoft/onnxruntime` returned 404 via web/API in the research session; version 1.32.0 and MIT licence were verified via PyPI and official docs instead. Re-check from another network before relying on repo metadata.
5. **OSM2World CLI stability:** site/docs describe a mature tool; OSM Wiki (older text) calls the CLI syntax unstable and elevation "very fragile and deactivated by default". Treat as a PoC gate, not an established fact about 0.4.0.
6. **Vulkan-on-Metal (unresolved):** Khronos has deprecated MoltenVK and recommends KosmicKrisp on Apple Silicon, while the wgpu README still says macOS Vulkan requires MoltenVK. Prefer native Metal on macOS; treat Vulkan-on-Metal as unverified until a PoC.
7. **`geo` far-from-origin precision:** fixes are documented on unreleased `main`, not in released 0.33.1. Treat as an open risk with regression fixtures, not a solved problem.
8. **quantized-mesh / 3D Tiles repository licences:** no LICENSE file found in either repository root (checked 2026-11-27). The OGC standards documents are royalty-free to implement, but deriving code from those repos is unverified.

### Resolution block — 2026-11-27 (GE-0002 research subagent)

All URLs below were accessed 2026-11-27. Each resolution is evidence only; no architecture decision is made here. The original eight conflict entries above are retained unchanged.

1. **OSM2World licence — VERDICT: Resolved (MIT authoritative for code reuse; documentation discrepancy remains).** Upstream `LICENSE.txt` on `master` is verbatim MIT text ("Copyright … OSM2World contributors", permission to use/copy/modify/sublicense/sell), and GitHub API `license` reports `spdx_id: MIT`. The OSM Wiki infobox still says "License: GNU LGPL (free of charge)" and categorises the page LGPL (last edited 2025-10-10), but that is a community-maintained secondary source contradicted by the project's own repository. The maintainer's site says "All code and assets are openly licensed. Use it freely for any purpose." **Unverified:** no explicit maintainer statement reconciling the old LGPL wiki text was found. Evidence: https://github.com/tordanik/OSM2World/blob/master/LICENSE.txt ; https://api.github.com/repos/tordanik/OSM2World/license ; https://api.github.com/repos/tordanik/OSM2World ; https://wiki.openstreetmap.org/wiki/OSM2World ; https://osm2world.org/ . **Consequence:** GE-0014/GE-0028 — MIT in the repo is the authoritative basis for vendoring/reuse; do not treat the wiki LGPL label as licence evidence.

2. **GlobalMLBuildingFootprints count — VERDICT: Resolved as documentation drift; exact current polygon count unverified.** The same current README still contains both figures: Introduction "detected **1.4B** buildings … between 2014 and 2024" (headline, with Updates through 2026-11-12) and FAQ "What does the data include? **999M** building footprint polygon geometries". The FAQ text is not updated by the dated Update entries and appears superseded/older (likely the 2022 combined-release figure — that linkage is an inference, **unverified**). Evidence: https://github.com/microsoft/GlobalMLBuildingFootprints/blob/main/README.md (Introduction, Updates, FAQ; accessed 2026-11-27). **Consequence:** dataset-size/capacity estimates (R-01, feeding GE-0003/GE-0006) should use ~1.4B as the published headline with a stated range; do not assert a verified exact count.

3. **WASI TCP/UDP default — VERDICT: Resolved; the `new()` doc sentence is stale.** Wasmtime 48.0.0 release notes (2026-08-20) state under Changed: "The `wasmtime-wasi` crate's default configuration now denies creation of TCP/UDP sockets by default" (PR #13936, merged). PR #13936 explains the old design ("allowed creation of TCP/UDP … but disallowed addresses … a brittle check") was replaced by denying TCP/UDP outright. In wasmtime-wasi 51.0.0 source, `AllowedNetworkUses` derives `Default` (all three `bool`s `false`) and `SocketAddrCheck::default()` rejects every address, while `allow_tcp`/`allow_udp` method docs correctly say "By default this is disabled". The `new()` doc bullet "TCP/UDP are allowed but all addresses are denied by default" was not updated and is wrong for 48+. Evidence: https://github.com/bytecodealliance/wasmtime/releases/tag/v48.0.0 ; https://github.com/bytecodealliance/wasmtime/pull/13936 ; https://docs.rs/wasmtime-wasi/51.0.0/wasmtime_wasi/struct.WasiCtxBuilder.html ; https://docs.rs/wasmtime-wasi/51.0.0/src/wasmtime_wasi/ctx.rs.html ; https://docs.rs/wasmtime-wasi/51.0.0/src/wasmtime_wasi/sockets/mod.rs.html . **Consequence:** GE-0005/GE-0025 — keep the defensive host code: explicitly deny by default and use an allow-list (`socket_addr_check`); never rely on `inherit_network()` alone, which only sets the address check.

4. **ONNX Runtime GitHub 404 — VERDICT: Resolved as a genuine upstream availability incident; canonical URL and licence recorded; cause unverified.** On 2026-11-27 both `https://api.github.com/repos/microsoft/onnxruntime` and `https://github.com/microsoft/onnxruntime` return HTTP 404 (API body "Not Found"; GitHub HTML 404), so the research session's 404 was reproducible, not a local error. Canonical URL remains **https://github.com/microsoft/onnxruntime** (PyPI `project_urls` Download → that repo's tags; official docs site links to GitHub). Licence **MIT** verified from PyPI metadata (`onnxruntime` 1.32.0, `license: MIT License`); the official site `https://onnxruntime.ai/docs/` returned 200. Third-party reports and the `onnx/onnx#8842` issue place the outage from ~2026-11-17; **unverified:** why the repo disappeared and whether/when it returns (no Microsoft/GitHub statement found). Evidence: URLs above plus https://pypi.org/pypi/onnxruntime/json ; https://github.com/onnx/onnx/issues/8842 . **Consequence:** GE-0006 — use registry packages (PyPI/NuGet/npm/Maven), pin and mirror artefacts locally, and do not depend on GitHub repo metadata or release-asset URLs; re-check repo availability later without blocking on it.

5. **OSM2World CLI stability / elevation — VERDICT: Resolved in favour of current upstream docs; the Wiki claims are stale.** Latest numbered release is 0.4.0 (2025-01-21), whose changelog includes "reasonable default elevation handler"; the download page additionally offers a "latest build" with the new subcommand CLI (`convert`, `help`, `gui`, `params`, `server`, `tileset`) described in the 2025-02-24 upstream blog post, with legacy command lines retained via fallback. 0.5.0 is still described as forthcoming ("will include") and no 0.5.0 release post exists; **unverified:** exact 0.5.0 release date. The OSM Wiki page (last edited 2025-10-10) still says the CLI syntax "is not yet stable" and elevation calculation "is currently very fragile and deactivated by default"; its linked configuration page dates that elevation note to May 2013. Evidence: https://github.com/tordanik/OSM2World/blob/master/doc/changes.txt ; https://osm2world.org/download/ ; https://osm2world.org/blog/2025/02/24/cli-subcommands ; https://osm2world.org/ ; https://wiki.openstreetmap.org/wiki/OSM2World ; https://fosdem.org/2026/events/attachments/BMMGNT-osm2world_3d_rendering_openstreetmap_data/slides/267176/osm2world_49jn01v.pdf . **Consequence:** GE-0014/GE-0028 — treat the Wiki wording as obsolete; retain a PoC gate that pins a specific build/CLI form and tests elevation output before relying on it.

6. **Vulkan-on-Metal — VERDICT: Resolved; both statements are current but describe different things.** On 2026-11-25 Khronos deprecated the Vulkan Portability Initiative and its provisional `VK_KHR_portability_subset` (removal planned with the mid-December SDK), and recommends **KosmicKrisp** for Vulkan on Apple Silicon with macOS 26+ (Vulkan 1.4 conformant, in the Vulkan SDK); MoltenVK remains recommended for Intel Macs, pre-26 macOS and iOS, and shipped MoltenVK apps keep working; the MoltenVK repo README carries the deprecation notice. The wgpu `trunk` README is factually current for wgpu: its table lists native Metal as first-class on macOS/iOS and marks Vulkan there as requiring the MoltenVK translation layer (it does not claim Khronos endorsement). **Unverified:** that wgpu's Vulkan backend works with KosmicKrisp (no wgpu statement found). Evidence: https://www.khronos.org/blog/from-portability-to-conformance-a-new-chapter-for-layered-vulkan-on-apple ; https://github.com/KhronosGroup/MoltenVK/blob/main/README.md ; https://www.khronos.org/news/archives/kosmickrisp-achieves-vulkan-1.4-conformance-on-apple-silicon ; https://github.com/gfx-rs/wgpu/blob/trunk/README.md . **Consequence:** ADR-0003/GE-0004 and ADR-0008 — prefer wgpu's native Metal backend on macOS; do not build around `VK_KHR_portability_subset`; any Vulkan-on-Metal path (KosmicKrisp) stays a PoC item.

7. **`geo` far-from-origin fixes — VERDICT: Resolved; fixes are on unreleased `main`, absent from 0.33.1, no newer release.** crates.io reports `max_version`/`newest_version`/`default_version` = **0.33.1**, published 2026-04-20, with no 0.33.2 or later as of 2026-11-27 (the recent `geo-types` 0.7.21 release is a different crate). `geo/CHANGES.md` on `main` has an "Unreleased" section with the far-from-origin/scale fixes: `Triangle::signed_area`/`unsigned_area` shift by the opposite coord so a needle-like triangle far from the origin no longer has area 0 (#1636); `Line::closest_point` overflow/underflow fix (#1604); `MakeValid` relative snap radius (#1640); `i_overlay` 9.2 fixes (#1628). The 0.33.1 changelog entry only records an earcut build-breakage fix (#1527). Evidence: https://crates.io/api/v1/crates/geo ; https://github.com/georust/geo/blob/main/geo/CHANGES.md ; https://github.com/georust/geo/issues/1636 ; https://github.com/georust/geo/issues/1604 ; https://github.com/georust/geo/issues/1640 . **Consequence:** GE-0003/GE-0011 — keep far-from-origin golden/regression fixtures; do not assume an upstream released crate contains these fixes.

8. **quantized-mesh / 3D Tiles licences — VERDICT: Partially resolved. (a) 3D Tiles: implementing from the OGC standard is royalty-free. (b) Repo-derived code: no licence grant found — unverified. (c) quantized-mesh implementation terms: not covered — unverified.** GitHub API: both repos have `license: null`, their `/license` endpoints return 404, and root contents listings contain no LICENSE file (3D Tiles root: README, CHANGES, Q-and-A, specification/, extensions/, releases/, etc.; quantized-mesh root: README.md, SPECIFICATION.md, schema/). Neither `README.md` nor `SPECIFICATION.md` in either repo contains a licence/copyright/royalty statement (text searched 2026-11-27). The OGC 3D Tiles 1.1 standard (22-025r4) states it is "available on a royalty free, non-discriminatory basis"; OGC's announcement says it is "free to download and implement"; OGC's Document License Agreement grants free-of-charge rights to "implement, use, copy, modify, … distribute" subject to retaining notices, but is copyright-only with no patent grant. **Unverified:** quantized-mesh is not an OGC standard, so no OGC royalty-free statement covers it; no evidence was found that the Cesium repos grant any code-reuse licence. Evidence: https://api.github.com/repos/CesiumGS/quantized-mesh ; https://api.github.com/repos/CesiumGS/3d-tiles ; https://api.github.com/repos/CesiumGS/quantized-mesh/license ; https://api.github.com/repos/CesiumGS/3d-tiles/license ; https://github.com/CesiumGS/quantized-mesh/blob/main/README.md ; https://github.com/CesiumGS/quantized-mesh/blob/main/SPECIFICATION.md ; https://github.com/CesiumGS/3d-tiles/blob/main/README.md ; https://docs.ogc.org/cs/22-025r4/22-025r4.html ; https://www.ogc.org/announcement/ogc-adopts-3d-tiles-v1-1-as-community-standard/ ; https://www.ogc.org/about/policies/document-license-agreement . **Consequence:** later 3D Tiles/quantized-mesh export tickets — implement from the published standards independently; do not vendor or copy code from these two repositories without separate legal verification.
