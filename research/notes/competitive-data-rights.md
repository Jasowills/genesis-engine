# Competitive Landscape and Data/Model Rights — Evidence Record

**Research date:** 2026-11-27 (all URLs below accessed on this date)
**Scope:** Competitive products, open datasets, map-to-3D tools and the licences/terms that govern their data, tools and models. Leads from `GENESIS_ENGINE_SPEC.md` §19 were treated as unverified until checked against primary sources.
**Evidence convention:** Statements are taken from official product docs, official GitHub repos/API, licence texts or terms pages. Anything not confirmed by a primary source is tagged **[UNVERIFIED]**. Thin or contradictory evidence is tagged **[THIN EVIDENCE]**. This document records evidence only; it makes no architecture decision and does not approve any dependency.

## 2. Data/model rights synthesis

### 2.1 Three separate licence questions must never be collapsed

1. **Tool/source-code licence** — e.g. CesiumJS/cesium-unreal Apache-2.0, OSM2World MIT, Open3D MIT, Blender GPL-2.0+/GPL-3.0 binaries, Houdini/RealityScan/Esri/Bentley proprietary. This governs whether Genesis can vendor, link, modify or redistribute the *software*.
2. **Dataset licence** — e.g. OSM/MS-legacy/Overture buildings ODbL; MS GlobalML and Overture places CDLA Permissive 2.0 / Apache-2.0; Google Open Buildings CC BY 4.0 **or** ODbL (electable). This governs geometry, tags and derived databases.
3. **Model/weight licence** — no candidate in this review publishes usable building/facade model weights. Google Open Buildings 2.5D explicitly keeps the model private; Microsoft publishes derived polygons only. Any future bundled model needs its own licence, commercial-use check and checksum record.

### 2.2 Concrete risks when redistributing generated assets

| Risk | Evidence | Consequence for Genesis |
|---|---|---|
| ODbL share-alike leakage into structured outputs | ODbL §4.4(b): extraction/re-utilisation of a substantial part into a new database is a Derivative Database; §4.4(c) triggers share-alike when a Produced Work from a Derivative Database is publicly used; OSMF ML guidance says substantial training extracts are Derivative Databases and overtrained models can recreate the training set. | A generated city exported as a **structured asset collection with retained source geometry/tags** can be treated as a Derivative Database → must be offered under ODbL, plus machine-readable alteration file (§4.6). A pure render/image is a Produced Work (§4.3 notice only) but could still be a Produced Work *from* a Derivative Database. |
| Attribution failure | OSM copyright page and 2026-09-10 attribution guidelines require credit and licence visibility; specific safe harbours for databases, interactive maps, static images, ML models, games. | A game-ready GLB shipped without embedded/source-adjacent attribution breaches ODbL; "© OpenStreetMap contributors" plus licence URL/link must travel with data and be visible in the Studio/game context. |
| Licence-election ambiguity | Google Open Buildings offers CC BY 4.0 or ODbL; the user picks. | If the election is not recorded, downstream users cannot know whether share-alike applies; record it per dataset snapshot. |
| Terms-of-service prohibitions | Google Maps Platform ToS §3.2.3(a)–(c); Map Tiles policies prohibit derivation/tracing/ML training; Cesium ion ToS §§2.2.2, 2.2.3, 2.2.4(xiii), 2.2.5, 2.3. | **Any pipeline that reads Google Maps/Street View/Photorealistic 3D Tiles or Cesium ion output as input to geometry extraction or model training is prohibited.** Generated assets derived from such content cannot be lawfully redistributed. Treat as a hard exclude in source adapters. |
| Source imagery rights | Microsoft and Google release **derived footprints**, not the satellite imagery; Google 2.5D uses Sentinel-2 but does not release high-res teacher imagery. | Genesis must not assume a right to bundle or redistribute imagery tiles; a "source image" fixture needs its own licence. |
| Trademark/brand rights | Microsoft legal notice says licences grant no rights to names/logos; OSMF trademark policy; Cesium ion logo requirement; Google brand-attribution rules. | Credit text must be used as attribution, not as endorsement; do not bundle logos into generated assets without separate permission. |
| Model weights | No public weights found for the footprint/reconstruction candidates. | A bundled open model is a **future, separately licensed decision**; do not assume dataset openness implies model openness. |

### 2.3 Required content of a compliant attribution/provenance record

The following fields are **evidence-derived requirements**, not an approved schema. They map to ODbL §§4.2–4.6, OSMF attribution guidelines (2026-09-10), CC BY 4.0, CDLA Permissive 2.0 §2.1, and Google Maps/Cesium attribution rules.

1. **Source identity** — dataset/product name, publisher, official URL, theme/version (e.g. "Microsoft GlobalMLBuildingFootprints, 2026-11-12 index"; "Google Open Buildings v3").
2. **Licence elected and URL** — exact licence name/version and URI, plus which option was chosen where dual-licensed; include the licence text/URI with any shared database (ODbL §4.2; CDLA §2.1).
3. **Attribution string** — exact required text, e.g. `© OpenStreetMap contributors`, `© OpenStreetMap contributors, Overture Maps Foundation`, `Contains information from DATABASE NAME, made available here under the Open Database License (ODbL)` (ODbL §4.3 example).
4. **Vintage / temporal scope** — imagery or survey dates, dataset release date, year band for temporal data (e.g. Open Buildings 2.5D 2016–2023).
5. **Spatial scope and filters** — bounding box/S2 cell/tile IDs, confidence thresholds applied, excluded areas.
6. **Derivation chain** — every transformation from source to asset (clip, reproject, simplify, extrude, infer height, roof rule, facade source), with tool name/version for each step.
7. **Observed vs inferred flags** — footprint known / height measured / height estimated / roof inferred / facade observed / facade procedural / facade AI-generated (spec §12), each with its evidence source.
8. **Model identity where used** — model name, version, checksum, licence, inference settings, device, attribution reference (spec §18); explicitly note if model weights are unreleased/remote.
9. **Derivative-database status** — whether the artefact is a Produced Work, a Derivative Database, or a Collective Database; if derivative, confirm ODbL licence offer and machine-readable alteration file/algorithm under §4.6.
10. **UI/display obligations** — where attribution must be shown (corner of viewport, splash screen, credits, README/metadata directory) and that it survives export to game engines (OSMF "Computer games and simulations" safe harbour).
11. **Third-party terms** — any overlay terms (Cesium ion, Google Maps, Bing, Nominatim/Overpass policies) and whether they were used only for display or for derivation.
12. **Timestamp and integrity** — record creation time, source checksum/snapshot ID, and a content hash of the generated asset bundle.

### 2.4 Datasets that are comparatively safe to bundle as small test fixtures

Subject to keeping the attribution/licence text with the fixture and confirming with legal review:

- **Microsoft GlobalMLBuildingFootprints** (CDLA Permissive 2.0): §3.1 says Results, including ML models, are unrestricted; §2.1 only requires sharing the agreement text. Best candidate for a small pinned tile fixture. Note the README licence typo "CLDA".
- **Google Open Buildings v3 / 2.5D** elected under **CC BY 4.0**: attribution required, **no share-alike**. Pin the elected licence in the fixture manifest. Small geographic cut-outs only; do not bundle the imagery.
- **Overture `places` records sourced from Foursquare** are Apache-2.0 (with NOTICE obligations); non-Foursquare places are CDLA Permissive 2.0. Overture `buildings`/`base`/`transportation` are **ODbL — not share-alike-free**, so only bundle if Genesis is prepared to publish the derivative under ODbL.
- **Do not bundle as unattributed fixtures:** raw OSM extracts, Microsoft Kenya/Nigeria/Australia legacy ODbL datasets, Cesium ion output, Google Maps/Street View/Photorealistic 3D Tiles content, or any proprietary vendor sample data.

## 4. Competitive differentiators visible from the evidence

Evidence-backed gaps that Genesis could claim (not decisions):

1. **Provenance as a first-class artefact** — none of the open map-to-3D tools reviewed (OSM2World, map3d/Mapforge, osm2threejs, gen-map, OVMG) advertises per-asset source/licence/inference records; GeoCity Forge and Scope City market provenance, indicating demand.
2. **Unified multi-source fusion** — Overture conflates sources but is a data product; no open tool reviewed combines OSM + MS/Google footprints + temporal height + user imagery with a single validation and correction loop.
3. **Local-first with lawful source adapters** — Cesium ion and Google Maps Platform terms explicitly restrict offline use/derivation/AI training; an open, local-first engine with an explicit "lawful source" boundary is a differentiator implied by those restrictions.
4. **Observed vs inferred labelling and validation** — spec §12's distinction is more rigorous than the confidence-threshold-only approaches documented by Microsoft/Google; Open Buildings 2.5D itself warns its confidence is uncalibrated.
5. **Editable, game-ready output plus round-trip** — splat vendors (ABot-Earth, ArcGIS Reality Gaussian splats, Houdini H22) produce impressive visuals but not obviously editable meshes; Open3D v0.20 renders splats alongside meshes but does not convert them to editable meshes.
