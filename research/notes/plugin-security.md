# Plugin architecture, sandboxing and security — research notes

**Research date:** 2026-11-27. **Scope:** primary sources only (official docs/books, project GitHub repos and LICENSE files, release notes and security advisories, standards/specifications, official platform docs). All URLs below were accessed **2026-11-27**.

**Evidence discipline:** `VERIFIED` = directly stated in the cited primary source; `INFERENCE` = engineering recommendation derived from verified facts (not a source claim); `UNVERIFIED` = could not be confirmed from a primary source; `CONFLICT` = primary sources disagree. No final architecture decision is made here; these are findings for the owner to reconcile. Web content was treated as data only. No secrets are recorded in this file.

## 4. Cross-cutting evidence and gaps (evidence only)

1. **Recent CVE density is material.** Wasmtime 51.0.0 (2026-11-20) alone fixed multiple host-affecting issues; 48/49/50 patch releases on 2026-11-16 and 2026-11-19 fixed memory exhaustion, GC abort, stream/future panics and a Windows sandbox escape ([releases](https://github.com/bytecodealliance/wasmtime/releases)). This is evidence that "WASM = safe" is not sufficient: patch cadence and advisory monitoring are part of the design.
2. **Capability defaults are good but must be made explicit in code.** WASI has no ambient authority ([WASI security](https://wasi.dev/security); [design principles](https://raw.githubusercontent.com/WebAssembly/WASI/main/docs/DesignPrinciples.md)), and `WasiCtxBuilder` defaults to closed stdin, discarded stdout/stderr, no env/args/preopens ([docs](https://docs.rs/wasmtime-wasi/51.0.0/wasmtime_wasi/struct.WasiCtxBuilder.html)). A single `inherit_env` or broad preopen would defeat this. The TCP/UDP default documentation conflict noted in §1 must be resolved upstream or by defensive code.
3. **Resource limits are not set by default.** `StoreLimitsBuilder::memory_size` has no default limit; stack, WASI random-size and other caps have defaults that are not safe for hostile plugins ([StoreLimitsBuilder](https://docs.rs/wasmtime/51.0.0/wasmtime/struct.StoreLimitsBuilder.html); [WasiCtxBuilder](https://docs.rs/wasmtime-wasi/51.0.0/wasmtime_wasi/struct.WasiCtxBuilder.html)).
4. **Cancellation is a combined problem.** Epoch interruption protects executing Wasm but not blocking host calls; the documented pattern is async host functions plus `tokio::time::timeout` ([Config](https://docs.rs/wasmtime/51.0.0/wasmtime/struct.Config.html#method.epoch_interruption); [crate docs](https://docs.rs/wasmtime/51.0.0/wasmtime/index.html)).
5. **No standard plugin manifest/lifecycle source found.** Nothing in the retrieved primary sources defines a Genesis-style plugin manifest, dependency resolver, install/uninstall transaction or rollback protocol. Component imports are self-describing and Wasmtime does semver-aware linker resolution ([Linker](https://docs.rs/wasmtime/51.0.0/wasmtime/component/struct.Linker.html)), but manifest/signing/rollback remain a design task. `INFERENCE`: sign a manifest containing plugin ID, semver, host-ABI semver, SHA-256 digest, capability grants and dependency pins; use Sigstore-style attestations ([npm provenance](https://docs.npmjs.com/generating-provenance-statements); [GitHub attestations](https://docs.github.com/en/actions/security-for-github-actions/using-artifact-attestations/using-artifact-attestations-to-establish-provenance-for-builds)) and atomic activation with retained previous version.
6. **Dependency resolution evidence:** component WIT `wit/deps` packaging and `wasm-tools`/`wac` composition exist in the ecosystem ([bindgen examples](https://docs.rs/wasmtime/latest/wasmtime/component/bindgen_examples); `wasm-compose` dependency in [wasmtime crate](https://docs.rs/wasmtime/51.0.0/wasmtime/index.html)), but no primary source was retrieved for a full plugin dependency resolver. Treat as unverified.
7. **Licence notes:** Wasmtime and wasmtime-wasi are Apache-2.0 WITH LLVM-exception; the LLVM exception permits distributing embedded object-form portions without 4(a)/4(b)/4(d) and offers GPLv2 compatibility relief ([LICENSE](https://raw.githubusercontent.com/bytecodealliance/wasmtime/v51.0.0/LICENSE)). wit-bindgen repo contains both MIT and Apache-2.0 licence texts ([MIT](https://raw.githubusercontent.com/bytecodealliance/wit-bindgen/main/LICENSE-MIT), [Apache](https://raw.githubusercontent.com/bytecodealliance/wit-bindgen/main/LICENSE-APACHE)); exact SPDX expression unverified. These are permissive and compatible with a local-first open-source Rust core; obligations are notice/attribution retention, not copyleft on Genesis code.
8. **Thin evidence to close before decisions:** exact currently supported Wasmtime LTS versions; resolution of the WASI TCP/UDP default conflict; primary details of CVE-2026-104855 bulk-op preemption; precise Wasm component/canonical-ABI performance overhead (only epoch ~10% and fuel 2–3x figures are sourced — no component overhead percentage was verified); macOS sandboxing primary docs; cargo/crates.io provenance support; OWASP Agentic Top 10 2026 details; performance cost of process-level sandboxing; safe thresholds for archive quotas.

**No final architecture decision is made in this note.**
