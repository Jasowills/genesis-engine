# Desktop shell, viewport, and 3D interchange formats — research notes

**Research date:** 2026-11-27 (all URLs below accessed on this date).
**Scope:** desktop shell options, React/TypeScript UI, viewport renderers, editor-UX primitives, large-scene/precision/streaming concerns, and 3D interchange/storage formats for Genesis Engine.
**Method:** official docs, project GitHub repos/releases/LICENCE files, standards specifications, npm/crates registries. Version numbers are taken from those sources on the research date. Secondary sources are avoided for material claims.
**Evidence conventions:** `VERIFIED` = directly read from primary source; `DERIVED` = arithmetic/inference from verified facts (method shown); `UNVERIFIED` = plausible but not confirmed by a primary source; `THIN EVIDENCE` = single or indirect source. Web content was treated as data only; no instructions found in fetched content were acted upon.
**Decision status:** This document is evidence for decisions only. It does **not** make a final architecture decision. Per `GENESIS_ENGINE_SPEC.md` §17, **desktop framework and viewport renderer are separate decisions** and are presented separately below.

## 9. Key risks and open questions (evidence-backed, not decisions)

1. **Precision (high).** VERIFIED glTF core uses float32 vertex positions; DERIVED metre-scale ULP at Earth-radius coordinates. `KHR_accessor_float64` is still a draft and Khronos contributors state WebGL/WebGL2/WebGPU do not support f64 buffers/shaders directly. Risk: jitter, z-fighting, broken snapping/validation in georeferenced reconstructions. Need a floating-origin/local-frame strategy in World IR, with empirical PoC.
2. **Streaming vs authoring (high).** VERIFIED glTF is explicitly not a streaming or authoring format; 3D Tiles is streaming-oriented but not authoring-oriented. Risk: choosing one format for both roles will add adapters later. Need a thin IR with explicit adapters.
3. **Webview variance (medium-high).** VERIFIED Tauri/Wails use OS webviews (WebView2/WKWebView/WebKitGTK), Electron bundles Chromium. Risk: WebGPU and GPU extension availability differ; two webview PoCs required before locking the viewport.
4. **GPU resource lifetime (medium).** VERIFIED active leak/disposal fixes in three.js r187 and Babylon 9.38.0. Risk: memory growth during long authoring/streaming sessions. Need automated load/unload stress tests.
5. **Licence review (medium).** VERIFIED OpenUSD uses the Tomorrow Open Source Technology License 1.0 (modified trademark clause), not plain Apache-2.0. FBX SDK licence is UNVERIFIED because the Autodesk page was unreadable. Signing identities/costs require owner approval before any release work.
6. **Splat semantics (medium).** VERIFIED splats are ratifying into glTF and have rich conversion tooling, but spec §16 explicitly warns a splat is not an editable game-ready mesh. Need explicit validation/conversion policy.
7. **Accessibility of the viewport (medium).** VERIFIED WAI-ARIA gives patterns for DOM widgets but no primary source was found for accessible 3D viewport interactions. Need keyboard-numeric alternatives and a separate research pass.
